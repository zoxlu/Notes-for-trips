---
name: process-raw
description: 處理 raw/ 裡尚未處理的素材，依照 CLAUDE.md 規則產生/更新 wiki 筆記，並自動分批、總結、commit。
---

依照 vault 根目錄 CLAUDE.md 的規則，處理 raw/ 裡尚未標記 `<!-- processed -->` 的素材：

1. 以每 5 個素材為一批，逐批處理，不要一次全部處理完才回報。
2. 每個素材的類型判斷、筆記 schema、欄位命名、重複比對、衝突標記，一律照 CLAUDE.md 的規則，不要自己另外發明欄位或命名慣例。`place` 筆記記得依 CLAUDE.md「子分類判斷原則」填 `place_category`；`food` 筆記記得填 `food_category`，並注意「名古屋鄉土限定」與「美食名店」是互斥的，不要同時掛兩者。素材裡如果有實用小知識（口感、交通轉乘訣竅等），依 CLAUDE.md「武林秘笈」章節整理進 `## 🗝️ 武林秘笈` 區塊，用疊加方式新增，不要整段重寫。
3. **主動抓取外部連結內容**：不管 raw 檔案本身是純連結，還是「家人的一段話 + 附上連結」這種混合形式，只要素材裡（或該筆記 frontmatter 的 `source_url`）提到部落格、網站文章、或一般網頁連結，都要用 web fetch 工具實際讀取該連結的完整內容，不能只依賴家人自己寫的那句話去判斷武林秘笈——家人分享時常常只留一句短評+連結，重點資訊是在原始文章/網頁裡，不去抓取就會漏掉大部分有價值的內容。YouTube 連結一樣要透過步驟2的 `yt-dlp` 指令抓逐字稿，不要只看影片標題或家人的短評。抓取到內容後，依 CLAUDE.md「武林秘笈」規則用自己的話摘要，**不要逐句照抄原文**（版權考量）。連結抓取失敗的話，在筆記加註「⚠️ 該連結內容無法取得，需使用者手動確認」，不要憑連結標題或網域臆測內容。
4. 所有檔案編輯直接用 Edit/Write 處理，不要設計 agent 式的檔案讀寫流程。
5. 本機圖片檔名不能包含空格（Quartz 會把空格轉成連字號，跟實際檔名對不上會造成連結失效）。如果素材裡的截圖是 Obsidian 預設命名（例如 `Pasted image ...`），先把檔案改名成連字號版本（`Pasted-image-...`），再繼續後續步驟。同一張圖片如果同時出現在 `image` 欄位、`raw_note` 欄位、內文嵌入語法裡，三處都要用同一個檔名，不能有落差。
6. 交叉連結：檢查這批新增/更新的筆記，以及既有筆記，依照 CLAUDE.md「交叉連結」規則做雙向比對（標題 + aliases），把符合的提及轉成 wikilink；同時依規則主動補充適合的 `aliases`。
7. 每完成一批：
   - 簡短總結這批新增/更新了哪些筆記、加了幾個交叉連結、有沒有待確認的衝突
   - git add + commit，訊息簡短描述這批更動的筆記
8. 全部素材處理完後：
   - 重新產生 `wiki/1.分類瀏覽/` 底下所有 index 頁面
   - 重新產生 `wiki/7.繃皮/` 底下所有個人分享頁
